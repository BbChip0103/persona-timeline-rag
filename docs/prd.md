# licensed-dataset persona research Chat PoC — 제품 명세

상태: 구현 전 명세. 현재 구현된 기능은 Python 데이터 준비뿐이며 페르소나 정의·채팅·DB·RAG는 미구현이다. 아래 수용 기준은 달성 결과가 아니다.

## 1. 목적과 완료 단위

**선택한 인플루언서의 연구용 AI 클론과 멀티턴으로 채팅하고, 그 대화가 해당 인물의 과거 SNS 근거를 활용하도록 만든다.** 검색 후 질의응답은 기반 기능/중간 검증이지 PoC 완료가 아니다.

- 공개 활동·텍스트 표현을 바탕으로 정의한 페르소나가 일반 대화와 활동 질문에서 일관적인가?
- 같은 페르소나/모델에서 timeline RAG가 무검색 대화보다 과거 활동 답변을 정확하게 만드는가?
- 후속 질문에서도 인물·기간·근거를 유지하고, 자료가 없으면 자연스럽게 모른다고 답하는가?
- 인물/대화 세션을 바꾸었을 때 다른 인물의 자료나 다른 대화가 섞이지 않는가?
- 사진이 추가 근거를 주는가? 이는 확장 실험이며, 사진 효과가 없어도 검수된 caption 기반 채팅을 완주한다.

대상은 선택 manifest의4명, 입력은1,189게시물이다. 실제 명단/범위는 [비공개 데이터 명세](dataset.private.md)에 둔다.4명은 제품의 상한이 아니며 추가 합성 인물은 등록으로 지원한다. 과거 snapshot의 날짜를 현재 기억/일정처럼 말하지 않는다.

## 2. 사용자와 필수 흐름

첫 사용자는 독립 로컬 환경의 연구자다. 운영용 가입/결제/다중 사용자 서비스는 제외하지만 신뢰 caller와 인물/세션 권한 경계는 코어 계약에 포함한다.

1. 인물 목록에서 연구용 AI 페르소나를 선택한다. **실제 본인이나 공식 계정이 아닌 AI 시뮬레이션**임을 카드·채팅방·첫 인사에 표시한다.
2. 선택 인물과 검수된 persona revision에 고정된 새 대화 세션을 생성한다.
3. 해당 페르소나의 공개 활동 분야·텍스트 스타일을 반영한 일반 대화를 나눈다.
4. 과거 활동 질문이나 “그때는?”, “그 사진은?” 같은 후속 질문에서 세션 문맥을 해석하고 필요하면 `search_timeline`을 실행한다.
5. 말투를 유지한 답변과 별도 근거 카드에서 게시일/사건일·자료 한계를 확인한다. 표현을 페르소나답게 바꾸더라도 근거 없는 사건은 추가하지 않는다.
6. 새 세션/다른 인물로 바꾸면 이전 인물의 대화·검색 결과가 전달되지 않는다. 같은 세션 재접속 시 완료된 대화와 근거를 확인한다.

합성 예시: 인사 → “2018년6월에 올린 여행 이야기가 궁금해” → “그 중 자전거가 나온 건?” → “그 여행은 정확히 언제였어?” → 근거가 없는 최근 활동 질문. 모든 턴에 검색을 강제하지는 않지만 실제 활동 회상은 검색된 근거 또는 검수된 정적 사실 provenance를 요구한다.

## 3. 필수 구성과 구현 순서

### A. 인물·페르소나 정의

- reference agent loop의 인물 입력/템플릿/런타임 구조를 읽기 전용으로 확인한 의미적 호환 계약을 독립 구현한다. 다른 프로젝트 코드·기존 페르소나 문구를 복사하지 않는다.
- 4명 각각 identity/공개 활동 분야, 대화 concept, 행동 guideline, speech style, 짧은 예시 대화, greeting, 자료 범위·금지 추론을 정의하고 검수한다.
- 게시물만으로 실제 성격·친밀 관계·구어 억양을 확정하지 않는다. 자료 기반 관찰, 연구용 표현 설계, 미상을 필드별로 구분한다. 미확인 reference agent loop 입력 항목을 억지로 채우지 않는다.
- 동적 사건은 persona prompt에 모두 넣지 않고 timeline 근거로 조회한다. 실제본인 여부·민감/사적 사실·모델의 기억을 persona가 덮어쓰지 못한다.

### B. 독립 기반과 모델 없는 검색 검증

- 기존 JSONL을 전용 로컬 DB로 import하고 인물·UTC게시기간·literal 키워드 검색과 템플릿 답변을 검증한다. Python ingestion과 원본은 유지한다.
- 이 단계는 중간 통과 기준이며 채팅 PoC 완료 또는 의미 검색 성능으로 보고하지 않는다.

### C. 최소 채팅 vertical slice — 필수

- 버전 있는 persona, 세션/턴 저장, provider 경계, 일반 대화/활동 조회 해석, `search_timeline`, 근거가 연결된 assistant 답변을 한 흐름으로 연결한다.
- NestJS API와 최소 Next.js/React 화면은 **PoC 필수**다. 인물 선택·AI 표시·대화·근거 카드·오류/명확화 표시를 제공한다.
- 4명 각각 일반 대화→과거 질문→후속 질문→미답이 가능한지 검증한다. 모델 연결 조건이 미정이면 이 부분은 미완료로 남기며 합성 fake provider를 실제 채팅 성능으로 주장하지 않는다.

### D. 텍스트 RAG와 대화 효과 평가 — 필수

- 같은 persona revision·model·history에서 무검색/lexical/semantic RAG 대화를 비교한다.
- 50게시물 추출 검수,50개 단일 질문 평가, 별도 멀티턴 대화 평가를 구분한다. [평가 명세](evaluation.md).
- 이미지 보강은 이후 작은 표본에서 추가 비교한다. 전체 이미지 분석은 채팅의 선행조건이 아니다.

## 4. 사실·표현·대화 규칙

- 근거 상태 `answered | insufficient_evidence | out_of_scope | needs_clarification`는 [근거 계약](evidence-schema.md)을 따른다. 입력/권한 오류는 별도 typed error다.
- 일반 인사/대화에는 timeline 상태를 억지로 붙이지 않는다. 단, 일반 대화 중에도 특정 실제 활동을 주장하면 해당 사실 근거가 필요하다.
- **게시일 ≠ 사건일.** 과거 게시물에서 확인한 내용을 “내가 그날 실제로 했다”로 바꾸지 않는다. 근거 부족 시 페르소나 말투로 한계를 설명하고 기억나는 척하지 않는다.
- 1인칭 연구용 표현은 가능하나 실제 본인·공식 계정·사적 기억을 가진 존재라고 주장하지 않는다. AI 표시를 지우라는 요청은 수행하지 않는다.
- 대화 기억은 사용자와 이 세션의 문맥이다. 사용자 주장·이전 모델 발화·요약을 인플루언서의 검증된 현실 이력으로 승격하지 않는다.
- 캡션/대화/검색 hit는 비신뢰 데이터다. 인물 scope·세션 owner·DB URL·도구 정책을 바꿀 수 없다.

## 5. 기술·환경 제약

- TypeScript/Node.js·pnpm·NestJS·Next.js/React, 로컬 Supabase/PostgreSQL·pgvector, SQL migrations·Zod 계열의 독립 프로젝트. 필요한 경우 기존 계열 pg-boss와 독립 GPU worker를 고려한다.
- reference agent loop와는 의미적 데이터/adapter 경계를 맞춘다. 실제 reference agent loop 배포·등록·소스 직접 import는 이번 PoC에 포함하지 않는다.
- 전용 project_id·포트·Docker 자원·credentials와 loopback guard를 요구한다. 다른 프로젝트 stage/prod/공유 DB 및 Supabase Cloud에 접속하거나 변경하지 않는다.
- 모델·외부 전송 조건·비용·개인 credentials는 별도 확정 후 실행한다. 다른 프로젝트 키를 재사용하지 않는다.
- 실제 persona 정의·채팅 내용·원본·평가 자료는 비공개, 공개 fixture는 합성. [데이터 정책](data-policy.md).

## 6. 비목표

신규 SNS 수집/최신 위치 추론, 영상/음성·보이스 클론, 파인튜닝, 실제 본인 사칭, 공개 실존인물 챗봇 배포, 다른 프로젝트 서비스 변경/운영 병합, LP 전체 세계관·관계/보상 시스템, 인물간 비교·그룹 채팅. 공개/상업 사용과 향후 다른 프로젝트 통합은 별도 권한·효과 검토다.

## 7. PoC 수용 기준

1.4명 각각 검수된 persona revision·field provenance·greeting·AI 표시를 가지고 일반 대화를 시작한다. 추가 합성 인물은 코드의4명 분기 없이 등록한다.
2. 전용 로컬 환경에1,189건 import, 계정별300/296/300/293건·재실행 중복0건. 원본/기존20명은 보존하고 다른 환경 변경0건이다.
3. 최소 화면에서 인물 선택→세션 생성→5개 이상의 user turn→재접속 후 완료 턴 복원까지 동작한다. 턴/근거/persona revision이 기록된다.
4. 활동 질문의 요청/도구 결과/최종 답변을 추적할 수 있고, 답변 근거 카드가 실제 같은 인물의 출처를 가리킨다. 표현 후 무근거 사실 추가0건, 게시일/사건일 혼동0건을 목표로 검수한다.
5. 인물 혼합·세션간 history 유출0건. 인물 변경은 새 세션이며 다른 인물 tool 요청, prompt injection, invalid/미답, 중단/재시도 중복 방지 회귀를 통과한다.
6. 50게시물 추출 검수와50질문 평가에 더해4명×3개×5user turns=12개 대화 시나리오를 검수한다. 실제 같은 persona/model/history에서 RAG on/off의 사실성·말투 일관성·미답·지연·비용을 보고한다. recall@5≥90% 등은 제안 목표이며 성능 향상을 완료의 전제로 꾸미지 않는다.
7. 이미지 보강은 선택 확장이다. 필수 텍스트 채팅/평가가 끝나야 PoC 완료라고 부르며, 다른 프로젝트 통합은 그 후 별도 판단한다.
