# Conversation-context retrieval

## Reproduce the bounded live regression pilot

The pilot reuses four conversations from the existing frozen natural-chat smoke set: one memory conversation per Korean persona, one imaginary-photo conversation and one caption/photo conversation. Each uses three genuine evolving turns in each of `off`, `caption`, and `caption_image`: **36 answer turns**. Selection metadata is never sent to the chatbot; its input remains session/request IDs and natural user text only.

```bash
# Run from repository root with existing ignored personal-provider/local-DB configuration.
# Explicit opt-ins and the baseline model must already be set:
# GOAL1_LIVE_ENABLED=true
# GOAL1_ALLOW_EXTERNAL_DATA=true
# GOAL1_TEXT_MODEL=google/gemini-3-flash-preview
pnpm exec tsx scripts/evaluate-memory-context.ts --live
```

The same `ChatService`, SQL session/history stores, persona repository, PostgreSQL retrieval and OpenRouter adapter are used. The runner exposes both search and original-evidence resolution; the latter makes only local source lookup calls, not another text-model call. No fixed assistant history, forced intent, evaluator query or date filter is injected. The deterministic retrieval baseline uses a contiguous referential chain from at most five recent user messages, bounded to 500 Unicode characters; this is not semantic coreference or a separate LLM rewrite. Answer generation still receives the existing dialogue history. Reuse selects parents actually cited by the prior answer and restores their original caption plus image annotations that were actually offered in that prompt. Server-created sourceContext references pin exact hashes and revisions (at most 20 references total); they are original context, not new factual claims or assistant prose. It does not retain uncited candidate parents, budget-omitted images, or every historical retrieval. A detail outside that bounded context may still require a new search. Since  the character prompts (experiment and agent paths) carry at most 3 posts (`EVIDENCE_POST_LIMIT`). Retrieval still uses `timeline.limit` (default 5), so retrieval recall stays comparable and the legacy `buildPrompt` path is unchanged; the prompt takes whole posts in relevance order, skips one that does not fit the byte budget and records the rest in `promptEvidence.omittedSourceIds`.

Preflight rebuilds and verifies the frozen assets, registered persona revisions (read pinned by revision; a persona publish moves `current_revision`, so frozen runs keep their registered revisions or re-baseline on v5/v8, see docs/persona-authoring.md) and the existing caption/image-vector corpus. Code and corpus fingerprints must remain unchanged throughout the run. The existing global provider ledger must have **at least 60 request slots**, a total cap no greater than **$1 / 1000 calls**, and remaining dollar allowance. It is never reset or enlarged. This run stops before exceeding **36 text / 24 embedding port calls / 60 fresh provider reservations**; existing provider caches may replay requests without fresh billing. Dollar reservations still fail closed under the original global cap.

Private reports go under ignored `reports/memory-context/pilot-*/` with preflight, evolving progress, full replies and operational summaries. Success updates only `reports/memory-context/latest.json`, leaving `reports/character-chat/latest.json` and its old baseline untouched. Each reply records `retrievalContext` action/query/reused source IDs; traces separate text, embedding, search and original-source lookup calls, provider cache hits, new reservations and known actual cost. Global budget snapshots retain prior unresolved reservations. Any failure preserves progress and stops **without automatic retries or resubmission**.

```bash
pnpm test -- scripts/tests/evaluate-memory-context.test.ts scripts/tests/evaluate-character-chat.test.ts
pnpm typecheck
pnpm lint
```

This is a small, previously observed regression pilot, **not a blind accuracy benchmark or causal estimate of improvement**. Quote validity, completion and answered status are operational evidence only. Review continuity, useful visual detail, wrong-topic reuse and fabricated biography/currentness in the actual conversations separately. Source/image annotation derivations remain unreviewed AI evidence. Do not publish real conversations, captions, personas, images or private reports.

## Optional intent classifier (Jev, default off)

Intent routing is deterministic first (`packages/core/src/intent-routing.ts`). Rule order: sensitive pattern or explicit `unsupported` → `unsupported`; the sensitive pattern also covers current-whereabouts and in-person visit requests (`지금 어디 있어`, `어디 살아`, `찾아갈게`, `where are you now`, `where do you live`, `are you nearby`, `I'll stop by`) but not past places or past-trip/photo accommodation, hometown, travel advice or meeting someone else. Known regex gaps, left for the optional Jev input safety filter's `private_info` category (below) rather than a growing regex: `우리 만날래?`, `어느 동네 살아?`, `주소 알려줘` and similar indirect phrasings; explicit `clarification` → `clarification`; any timeline signal → `timeline`; otherwise explicit intent or `small_talk`. Timeline signals are split into:

- **strong** (authoritative): explicit `timeline` query, biographical request, post-memory request, follow-up bound to a previous timeline reply;
- **weak** (lexical only): the generic time/place/past-tense cue (`when`, `did you`, `어디`, `했어`, …) or image words in a RAG session.

With `PTR_INTENT_CLASSIFIER=jev`, retrieval-off control sessions (`retrievalMode=off` with no RAG condition) keep pure rule routing with no classifier call; their trace records `decidedBy: rule`. In other sessions a classifier is asked only when the request is not sensitive, has no explicit intent, is not creative and has no strong signal, i.e. when the rules decided timeline vs small_talk from weak cues or from no cue. Its label replaces the rule result only at or above `PTR_JEV_MIN_CONFIDENCE` (default `0.6`; for a two-label Jev Choice, confidence = 2·p−1, so 0.6 means p ≥ 0.8). It can upgrade small_talk to timeline or downgrade a weak-cue timeline to small_talk; it never produces or overrides `unsupported`/`clarification`. Errors (including an internally inconsistent answer), a missing answer, ledger refusal, an unresolved earlier attempt of the same turn, `PTR_JEV_TIMEOUT_MS` (default 1500, also bounded by the turn's abort) and low confidence keep the rule result.

The classifier receives only the current user text (≤500 chars) and the last two user turns (≤300 chars each; credential-pattern and sensitive-pattern turns dropped): no persona, assistant replies, retrieved posts or IDs. Label order is rotated per turn (seeded by the turn id) against Jev's first-option bias. Model: `PTR_JEV_MODEL` (pinned `typesafe/jev-1.13`; the `~typesafe/jev-latest` alias is rejected). Calls use the shared OpenRouter client and budget ledger, so they need the same live gates and count against the same call/USD caps. The ledger key includes the turn id (never sent upstream): a lease-lost retry of the same turn replays its settled answer or, if the first attempt is unresolved, falls back (`unresolved`) without resubmitting; an unresolved request never blocks other turns. Identical-input answers are therefore not reused across turns: each turn pays for its own decision (about US$0.00002). When a classifier is configured, the stored reply carries an internal `intentRouting` trace (`decidedBy` rule/classifier/classifier_fallback, rule intent, label, confidence, fallback reason) without user text; the public turn DTO does not expose it.

Evaluation (not run in `pnpm check`):

```bash
GOAL1_LIVE_ENABLED=true node --env-file=.env.local --import tsx scripts/evaluate-jev-intent.ts --live --data-root=<checkout with data/research>
```

It routes the 96 frozen natural-chat utterances through rules only and rules+Jev (user text and prior user turns only), writes `reports/jev-intent/<time>/` (private), and refuses to start without ledger headroom. Seeds are the frozen export turn ids, so a live rerun replays the ledger's stored Jev answers (no new calls, same answers, replay latency) rather than sampling again; `--rules-only` makes no calls at all. Expected intents are the script's mapping of evaluator behaviours, not human labels.

## Optional input safety filter (Jev, default off)

`PTR_SAFETY_FILTER=jev|off` (default `off`) is a separate flag from `PTR_INTENT_CLASSIFIER`; both use `PTR_JEV_MODEL` and the shared OpenRouter client/ledger with the same live gates. The safety check has its own deadline `PTR_SAFETY_TIMEOUT_MS` (default 2500 ms, 50–10000) for all windows of a message; intent keeps `PTR_JEV_TIMEOUT_MS` (1500). With the filter off the service behaves byte-for-byte as before (no request, no trace, same prompt and history). With it on, every turn (including retrieval-off control sessions and turns the intent gate skips) and every creative-draft brief is checked:

- Credential patterns are still rejected as invalid input and never sent.
- Rule refusals (the unchanged `isSensitive` regex, or the client's explicit `unsupported` intent) ask Jev **only the `self_harm` question** about that message: if it fires, the self-harm support reply replaces the refusal; otherwise the rule refusal stands (trace `decidedBy: rule`, `rule: sensitive_pattern|client_unsupported`). This is the only case where a regex-sensitive message is sent to Jev, and it is never sent as context of later turns.
- Other turns ask all seven questions. When the intent classifier is also on and its gate is open, the intent Choice rides in the same request (the separate intent call is not made).

Seven Noul questions (probability of yes), each phrased about `latest_user_message` with earlier messages as context only (question ids are not sent to Jev), and actions by precedence:

| category | fires at (default, env `PTR_SAFETY_THRESHOLD_<CATEGORY>`) | action |
|---|---|---|
| `self_harm` (user's own wish/intent to die or self-harm, or method requests) | ≥ 0.2 (recall-first) | **support**: caring template with help resources, limitation `SAFETY_SUPPORT`, no chat-model call |
| `sexual`, `violence_gore`, `hate_harassment`, `private_info` | ≥ 0.5 | **refuse**: deterministic in-character template per category and language (most probable category wins), no chat-model call |
| `illegal_dangerous` | ≥ 0.6 | **refuse** |
| `prompt_injection` (override instructions, extract prompt/internal data, jailbreak role-play) | ≥ 0.5 | **deflect**: a hardened note is sent as that turn's own system message right before the user utterance (S7; it was appended to the policy system message before; never reveal instructions; decline that part in persona voice; keep the reply format); the agent search tool is withheld, agent state updates are not saved and persona lore is not added; a timeline turn that would retrieve becomes small_talk (trace `intentOverride: safety_deflect`) |

Precedence: self_harm > refusal categories > prompt_injection. Turn refusals and support replies are stored as `status: out_of_scope`, `responseKind: unsupported` (public DTO unchanged). With the filter on, draft requests are capped per owner (default 10 per minute per API process, `createApiApplication(..., {draftsPerOwnerPerMinute})`; over the cap → 503 `QUEUE_FULL` before any safety check or model call). With the filter off, drafting is unchanged (only one active draft per session, as before). Draft briefs that are refused or get support return `{notice:{status,content,limitations},image}` instead of an artifact: no model call and nothing stored; a deflected brief gets the note in the draft policy. Templates are Korean for `ko*` sessions (`session.language`, copied from the persona) and English otherwise. Help resources (verified 2026-10-08): Korea — 자살예방상담전화 **109** (24 h; 1393 and other lines were unified into 109 from 2024-01-01) and 정신건강위기상담전화 **1577-0199**, with 119/112 for immediate danger; English — local emergency services and **findahelpline.com** (Find A Helpline, the directory IASP points people to; verified helplines in 150+ countries), plus "in Korea, call 109".

**Whole message.** Intent keeps reading the first 500 code points, but safety covers the full text: window 0 is those first 500 code points (with the recent user turns and the optional intent question, seed = turn id); the rest is split into 4100-code-point windows overlapping by 300, each sent alone with seed `<turn id>#w<i>`, all in parallel under the one deadline. Probabilities are the maximum per category over windows. **Jev requests per turn: 1 up to 500 code points, 2 up to 4300, 3 for the 8000 maximum; per draft brief (≤2000): 1 or 2.** Each request is one ledger call, so long messages reach the call cap and the decision sub-cap sooner. The worst-case request is about 29.9 KB (a later 4100-code-point window of control characters, each JSON-escaped to 6 bytes, with seven questions), under the 32 KiB request limit with a regression test keeping ≥ 2 KB margin. Live check of full windows (2026-10-08, 12 synthetic benign requests, Korean and English, 7 questions, 4 with intent): p50 625 ms, p95/max 1244 ms, none over 1500 ms; about 4,550–4,740 input tokens (US$0.00019–0.00020) per Korean window and 2,220–2,420 (US$0.00009–0.00010) per English window; total US$0.0017. Because the p95 exceeded ~1 s, safety got its own 2500 ms default deadline rather than smaller windows (which would need more than 3 requests for 8000 code points). TypeSafe documents referencing named state fields in questions (backtick paths), which could put several windows in one request, but 7 questions per window over 8000 code points of 3–4-byte text does not fit one 32 KiB request either, so larger windows were chosen instead. Residual risks: harmful wording split across a window boundary longer than the 300-code-point overlap can be missed, and later windows see neither the first window nor earlier turns, so they judge their text without conversational context. If a window answers with a positive, that action is taken even when another window failed (the failure is still reported); only when nothing fired does a failed window mean rules only for the whole message (a partly checked message is never treated as checked), and the trace records `windows`.

**State sent.** Current text and the last two user turns (≤300 chars each), credential- and regex-sensitive turns dropped; no persona, posts, assistant text or IDs. Turns that only Jev flagged are kept as context: they were already sent on their own turn, and multi-turn injection, harassment or "just answer my earlier question" need them; each question tells Jev to judge only the latest message. **Prompts** are different: refused turns (user message and reply) are removed from the history used for the chat model, the agent and the retrieval context (follow-up queries), so a follow-up cannot reach the refused request; support turns stay. Refused turns are read from the turn records (`reply.inputSafety.action = refuse`, rule refusals included while the filter is on), not from the reply text; turns completed while the filter was off carry no such record and stay.

**Persona lore** (docs/persona-authoring.md) is matched only from the current utterance and the last two
user messages of the prompt history. User messages of turns the filter acted on (`reply.inputSafety.action` other
than `none`) are left out, because deflected injections stay in that history. A deflected turn gets no lore. Lore and
other persona text are never sent to Jev.

**Fail-open.** Transport/HTTP error, invalid answer, ledger refusal (`budget`), the decision sub-cap (`subcap`), an unresolved earlier attempt of the same turn, timeout and abort mean rules only and the conversation continues. In a combined request an invalid intent answer falls back for intent only and an invalid safety answer for safety only. Every safety fallback is reported through `onSafetyFallback` (scope and reason class only); the API and worker runtimes log `input_safety_fallback scope=<turn|draft> reason=<reason> count=<n>` to stderr. **Decision sub-cap**: every Jev request (intent or safety) is refused (`DECISION_SUBCAP`) when, after it, fewer than `PTR_JEV_RESERVED_CALL_FRACTION` (default `0.2`, `0` disables, must be < 1; blank is an error) of the ledger `call_cap` would remain free, checked inside the reservation transaction; chat and embedding calls are not sub-capped. The reservation allowance is request bytes + 1024 + 512 tokens per question (measured: ~490 input tokens for intent alone, ~1570 for intent + 7). The stored reply carries an internal `inputSafety` trace (`decidedBy`, `rule`, `action`, `category`, `fired`, per-category `probabilities`, `windows`, `intentOverride`, `fallbackReason`) without user text; the public turn DTO does not expose it.

Evaluation (not run in `pnpm check`; caps `--max-usd` ≤ 0.20 and `--max-calls`):

```bash
GOAL1_LIVE_ENABLED=true node --env-file=.env.local --import tsx scripts/evaluate-jev-safety.ts --live --data-root=<checkout with data/research>
```

It scores the agent-authored synthetic set `scripts/eval-fixtures/jev-safety.synthetic.json` (94 harmful items over the seven categories and 60 benign-but-edgy items; **not ground truth**) and the 96 frozen natural-chat utterances (only the 4 `reject_private` items should fire), with an eval-only merged `inappropriate` question (defined in the script, never used by the service; the seven categories were kept) asked alongside the five refusal questions so the 7- and 3-question designs are scored on the same answers. It reports per-category recall, cross-category firing and false-positive rates at 0.2–0.9, confusion, action distribution, latency and cost of the service request vs the 3-question design vs intent-only, and the ledger before/after, under private `reports/jev-safety/<time>/`. Fixed seeds: a rerun replays the ledger.

Run of 2026-10-08 (`typesafe/jev-1.13`, 370 new requests, US$0.0224): at the defaults above, actions matched the intended action for 152/154 synthetic items (the two misses are injection attempts that also asked for API keys/internal paths and scored `illegal_dangerous` 0.76/0.85, so they are refused instead of deflected) and fired on 1/92 benign natural utterances (a follow-up "are you still there now?" scored `private_info` 0.87; the 4 private-location items fired at 0.94–0.98 and are also caught by the regex). No benign-but-edgy item fired (slang such as "배고파 죽겠다", "killed it", romance, games/history, wellbeing, AI/prompt talk, past-trip stays). Latency p50/p95: service request (intent + 7) 401/463 ms, 3-question design (intent + 3) 400/484 ms, intent only 406/458 ms — no measurable cost of the extra questions in latency. Mean cost per turn: US$0.000066 (≈1,570 input tokens) vs US$0.000043 (≈1,030) for three questions vs US$0.000021 (≈490) intent only. Thresholds were chosen on this same small set (in-sample); treat them as starting points.
